# Legacy pallet → V2 migration guide

Two theme systems coexist right now: `LocalPallet` (68 constructor fields + ~65 more hardcoded `val`s, flat,
screen-specific names like `fapHubActiveColor`) and `LocalPalletV2` (`FlipperPalletV2`, nested by semantic role:
`text.title.primary`, `surface.navBar.body.accentBrand`, `action.success.background.primary`). 230 files still use
the legacy one; 67 already use V2.

**Policy:** don't do a blanket rename. Migrate a screen's colors to V2 when you're already touching that screen
for a UI change — never touch a screen only to swap its theme calls. Reference this doc for the mapping instead
of re-deriving it. Never hand-edit anything under `.pallet.generated` — it's autogenerated and gets overwritten.

## Text and icon opacity ladder — the one that needs judgment

Legacy's `text100..text4` and `iconTint100/80/30/16` are an *opacity* ladder — same hue, decreasing alpha, no
semantics. V2's `text.{title,body,label,caption}.{primary,secondary,tertiary,whiteOnColor,blackOnColor}` is a
*role* ladder — which typographic role, not how faded it looks. There is no formula between them; each call site
needs one look at what the text actually is:

- Screen/section headline → `text.title.primary`
- Regular readable content → `text.body.primary` / `.secondary` / `.tertiary` (roughly matches legacy's
  `text100` → `text80/60` → `text40/30` fade-out, in that order)
- Small UI chrome (chip labels, timestamps, counts) → `text.label.*`
- Helper/caption text under a field → `text.caption.*`
- Text sitting on a colored/brand background → `.whiteOnColor` / `.blackOnColor`, not a body/title role

`iconTint100/80/30/16` → `icon.neutral.primary/secondary/tertiary` similarly by prominence, not by literal alpha
match.

| `fapHubBuildStatusFailed*` | `action.danger.background.*` / `action.danger.text.*` |
| `warningColor` / `successfullyColor` | `text.semantic.warning` / `text.semantic.success` |

| `keySubGHz` / `keyRFID` / `keyNFC` / `keyInfrared` / `keyIButton` | `category.background.subGhz/rfid/nfc/infrared/ibutton` (+ matching `category.icon.*`, `category.text.*`) | V2 also already has `badUsb`, `gpio`, `games`, `media`, `tools`, `bluetooth` — categories legacy never modeled at all |
| `keyUnknown` / `keyDeleted` / `keyFavorite` | no exact match | closest are `category.background.tools` (unknown) and `icon.neutral.tertiary` (deleted); `keyFavorite`'s star-gold has no V2 role — treat as a bespoke color, see `FlipDroidPalletExtras` |

## Bespoke widget colors — not a gap, by design

Already extracted to [`FlipDroidPalletExtras`](src/commonMain/kotlin/com/flipperdevices/core/ui/theme/composable/pallet/FlipDroidPalletExtras.kt):
NFC card visualizer, battery gauge, MfKey32 highlight, key-emulate bubble, infrared editor canvas, hex-keyboard /
NFC-editor substrate, on-Flipper OLED tint. Use that object directly; don't look for a V2 role for these.

## Not yet migrated as of this doc

`fapHub*` non-status fields (`SwitchBackground`, `SelectedBackgroundColor`, `DividerColor`, `SortedColor`,
`CategoryText`, `Active/InactiveColor`, `DeleteDialogBackground`), `tabSwitch*`, `screenStreamingBorderColor` /
`NotConnectedColor`, `reportBorder`, `flipperDisableButton`, `disableSwitch`, `progressBarGray`, `onAppBar`,
`disableBackgroundSwitch`. These map onto existing `surface.menu.*` / `action.neutral.*` / `surface.border.*`
roles reasonably well but weren't given a final call here — decide per call site when that screen is touched,
following the same "role, not alpha" reasoning as the text ladder above.
